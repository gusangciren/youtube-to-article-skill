# 03 · 排版与 Obsidian 兼容性

---

## 一、小标题

### 不编号

```
✅ ## 赫尔莫西的洞穴：一天必须有六个小时
❌ ## 一、赫尔莫西的洞穴：一天必须有六个小时
❌ ## 1. 赫尔莫西的洞穴
❌ ### 2.1 为什么要设立公司
```

**为什么**：序号会让标题看起来像目录或步骤清单，
而且会和正文里的列举、公众号版式的自动编号打架。

**唯一例外**：原文**本身就是**「N 条原则 / 信条 / 清单」时，用加粗条目标题：

```
**1. 核心命题——法则名**
正文……
```

编号保留原文顺序。

### 层级

- `#` 一级标题（文章标题，只有一个）
- `##` 二级标题（主要章节）
- `###` 三级标题（章节内的分节）

## 二、加粗：Obsidian flanking 铁律 ⚠️

### 为什么会出问题

Markdown 加粗能否解析，取决于 `**` 两侧的「连接性」。
CommonMark 的 flanking 规则是**按英文空格设计的**，对中文全角标点极易失效。

失效的表现：在 Obsidian 的**编辑模式（Live Preview）**里，
加粗不生效，直接露出裸星号 `**这是重点**`。
阅读模式却可能显示正常——所以很容易漏检。

### 判据（只有两条）

**开标记** `**`：
- 后面紧跟的字符**不能是空白**；
- 若后面紧跟的是标点/引号，则它**前面**必须是空白或标点。

**闭标记** `**`：
- 前面紧跟的字符**不能是空白**；
- 若前面紧跟的是标点/引号，则它**后面**必须是空白、标点或行尾。

另外：**禁止跨行未闭合**，`**` 的开与闭必须在同一行内成对。

### 三个最常踩的雷

共同特征：**内侧贴标点/引号，外侧是普通字**。

| ❌ 错 | ✅ 对 |
|---|---|
| `**"引号内容"**` | `"**引号内容**"` |
| `**术语（英文）**与…` | `**术语**（英文）与…` |
| `**「沼泽」**里` | `「**沼泽**」里` |
| `**「过家家」（Playing House）**` | `「**过家家**」` |

### 句末句号怎么放

`**……。**` 的处理**分两种情况**：

```
✅ 句末/行尾：**这就是全部答案。**          （句号在行尾，其后无内容 → 无碍，保留）
❌ 句中：**定价。**你刚出道的时候            （句号后还接正文 → 违规）
✅ 修正：**定价**。你刚出道的时候
```

别为了追求"内侧纯普通字"而把所有句号都往外挪——
**行尾的句号留在加粗内即可**。

### 校验

```bash
python scripts/check_article.py 成稿.md
```

看 `[3]` 两项：
- 加粗闭合（`**` 偶数）—— 奇数行 = 跨行未闭合
- 加粗 flanking 连接性 —— 逐个列出违规行

**这两项不过，不得交付。**

## 三、链接：拆成代码块

**微信公众号渲染不了 Markdown 链接 `[文字](url)`**——不可点击，也常常不显示。

### 做法

```
❌ [Paul Graham 的这篇文章](https://paulgraham.com/ds.html)

✅ Paul Graham 的这篇文章：

```
https://paulgraham.com/ds.html
```
```

三个反引号独立成行，URL 独占一行，再三个反引号收尾。
公众号的代码块横向滚动、不换行，长链接恒占一行，不会破坏排版。

演讲里口头提到的网址（"去这个网站 slash 某某"）同理，裸放代码块，
**别硬造 `[ ]()`**。

### 若发布渠道不是公众号

发到自己的博客 / GitHub / Obsidian Publish 的话，可以保留标准 Markdown 链接。
这是可配置项，见 SKILL.md 第 8 节。

## 四、段落与呼吸

**段落偏密**：一个独立事件、一个意思、一个转折 = 一段。
不要把多个事件堆进同一大段。

允许把总结句、承上启下的短句单独成段，作为呼吸点：

```
……他用了整整一年才想明白这件事。

这就是我人生的开端。

于是我决定退学。
```

## 五、引用块

整理稿**允许**用引用块，用来强调：

- 反常识的提醒
- 旁白式金句
- 讲者的原话

```
> 大多数人首先想到的是他们想要表达什么，然后为想法寻找受众。
> 你必须从相反的角度切入。
```

⚠️ 风格稿（「演讲变文章」技能）**不允许**引用块，别搞混。

## 六、清单体 / 信条体素材

当原文是「N 条原则 / 信条 / 清单」时：

- **编号加粗条目标题**：`**N. 核心命题——法则名**`，比纯小标题更贴原结构、更易扫读
- **开头加粗导语 + 分隔线**（可选）：把核心论点加粗置于最前，`---` 分隔后接正文
- **引用块强调金句**
- **术语缩写完整标注**：如 每次下单成本（CPO，Cost-Per-Order）

⚠️ 编号条目标题**只用于**原文本身就是清单体的素材。
普通的章节小标题仍按「不编号」处理。
